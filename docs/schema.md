# Graph schema: spec vs. what the graph now carries

Build spec Part 3.1/3.2 required **five node types** and **seven edge types**. The
shipped graph had exactly two: `Function` nodes and `CALLS` edges
(`src/friction/arms.py:emit_arm` kept only those and discarded everything else the
SCIP index already held). Task 3 restores the rest.

The emitter is `friction.arms.emit_typed_arm` (assembled by `build_typed_arm`);
the structural edges come from `friction.scip.extract.structural_edges`, the
config reads from `friction.config_keys`, and the whole thing round-trips through
`friction.loader` (all five labels via `merge_set_label`, all seven relationship
types via `single_pattern_create`, batches ≤ 1024). `build_instance`'s arm B now
emits this typed graph in place of the CALLS-only one.

## Node types

| Spec node | Shipped before | Present now | source |
|---|---|---|---|
| `Function` | yes | **yes** | SCIP function defs not under a test root |
| `Class`    | no  | **yes** | SCIP class defs |
| `File`     | no  | **yes** | distinct SCIP document paths |
| `Test`     | no  | **yes** | function under a `tests/` root or named `test_*` |
| `ConfigKey`| no  | **yes** | distinct `settings.<NAME>` names |

## Edge types

| Spec edge | Endpoints | Shipped before | Present now | source |
|---|---|---|---|---|
| `CALLS`        | Function→Function | yes | **yes** | SCIP reference inside a def span |
| `DEFINED_IN`   | Function→File     | no  | **yes** | each function def → its file |
| `HAS_METHOD`   | Class→Function    | no  | **yes** | method whose enclosing class is defined |
| `INHERITS`     | Class→Class       | no  | **yes** | base class named on the class-header line |
| `IMPORTS`      | File→File         | no  | **yes** | module-scope reference resolved to another file |
| `READS_CONFIG` | Function→ConfigKey| no  | **yes** | `settings.<NAME>` read, from the reading function |
| `COVERS`       | Test→Function     | no  | **yes (dynamic overlay, sparse — see below)** | executed test→function edge (`friction.trace`) |

## Honest caveats — read these before trusting a count

- **COVERS is real but sparse, and it is not a static edge.** The trace produced
  137 test-sourced edges; **36** joined arm B's type-resolved nodes. The gap is
  the documented class-body/import-time frames (`<module>`, model-class bodies)
  and names the tracer's `co_qualname` cannot rejoin to a SCIP symbol. 36 edges
  against 57,314 CALLS is **not** broad coverage — COVERS says "this test
  executed this function," and it says it for a small, honestly-counted set, not
  the whole graph. Do not read a populated `COVERS` type as "the suite covers the
  code." It is folded into connectivity analysis by `friction.covers3`, not
  asserted graph-wide.
- **READS_CONFIG is substantial and static: ~610–630 edges, ~145 distinct
  ConfigKeys per instance — nowhere near zero.** Of ~1,010 `settings` references,
  ~743 resolve to a `.NAME`; ~266 are `settings` used without an attribute (passed
  as an argument, `hasattr`, etc.) and ~14–16 are module-scope reads that make a
  ConfigKey but no edge. All disclosed by `extract_config_reads`'s stats.
- **Dropped edges are counted, not hidden.** Per instance ~700 `CALLS` and
  ~300–370 `IMPORTS` reference a canonical/file with no collected definition
  (dunders, attributes, stub-only symbols); they are dropped rather than emitted
  against a phantom id, and reported in `dropped_edges`.
- **Test nodes outnumber Function nodes** (~15k vs ~7.6k) because django's suite
  is enormous; every `test_*` method and every helper under a `tests/` root is a
  `Test`. This is expected, not a labeling error.
- Every node carries the string `sid` mirror the engine's `algo.*` set queries
  address, alongside the integer `id` the engine matches on.
